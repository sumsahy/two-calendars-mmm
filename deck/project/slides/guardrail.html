So it never happens again

A refresh gate that an LLM can only make stricter

1

Schema

The LLM reads each vendor spec and answers in fixed fields: grain, calendar, week start, date label.

2

Grounding

Each claim quotes the spec word for word, and the quote itself must say that value.

3

Spec scan

A plain rule-based reader checks the same spec; any disagreement blocks.

4

Data check

Claims must match the file: date spacing, weekday, coverage, no gaps or bad values.

5

Contract

Unknown blocks. Weekly data is split by day and must conserve spend to the cent.

Proven by tests

  • A quote with one word swapped is rejected
  • A fiscal-month file can’t pass as calendar months
  • A silent switch to week-ending dates is blocked
  • TV that doesn’t cover the sales window is blocked

0 of 9 misaligned vendor specs got through. Version 1 used fuzzy matching; the independent review broke it three ways, and each break is now a test.

Why an LLM at all: a Sunday date could mean week starting or week ending, and a first-of-month date could be a fiscal month. Only the spec says which. The LLM reads what the data can't say; the data and the rule-based scan check what the LLM can't be trusted to say. The eval labels and recorded readings were both written by Claude, so the score is not independent; a live Groq run is the independent check. Known gap: a units change (spend sent in thousands) needs the previous refresh as a baseline.
